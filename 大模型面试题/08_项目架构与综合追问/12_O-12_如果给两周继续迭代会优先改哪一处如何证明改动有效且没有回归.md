##### 🎙️ 30 秒高频口答精要 (电梯演讲 / 直击要害)

若有两周继续迭代，我会优先补齐两个生产级边界：第一，SuperMew 的“同名文档更新跨存储一致性与零停机切换”：目前删除旧向量并重新建索引存在短暂不可用与写放大，需实现基于 Milvus Partition 与 Collection Alias 的蓝绿无感滚动发布；第二，DataPilot 的“Python 沙箱产物出口脱敏网关”：目前脱敏主要覆盖 SQL 查询层，需在容器出口增加图表元数据与标准输出的二次脱敏拦截器。验证手段是在 300 例分析集（Analysis Set）上执行全量自动化回归，并在投产上线前一次性解封严格隔离的 200 例盲测验证集（Validation Set），确保新特性生效且大盘指标零回退。

##### ⏱️ 60~120 秒深度展开 (系统架构 / 机制与推演 / 逐行源码讲解)

两周迭代的工程规划、落地难点与防回归验收闭环：

1. **SuperMew 迭代重点：Milvus 别名零停机滚动更新（Zero-Downtime Re-indexing）**：
- **痛点**：知识库文档修订或分块策略升级时，直接在原集合上 `delete_by_ids` 会导致 Milvus 产生海量 Soft-deleted 标记与索引碎片，检索延迟出现显著毛刺，且删除与写入非原子操作；
- **改造**：为新批次创建带时间戳的影子 Partition 或影子 Collection，在后台完成 Embedding 与原生 BM25 索引构建后，通过 Milvus Alias 别名（`utility.alter_alias`）原子指向新集合，毫秒级完成流量切换，再异步清理旧版本，实现零写放大与零停机。

2. **DataPilot 迭代重点：Python 沙箱可信出口脱敏网关（Egress Sanitizer）**：
- **痛点**：目前 SQLGuard 已做到 SQL 查询的方言级 AST 拦截与行数截断，但模型生成的 Python 代码在沙箱中可能通过 `print()` 或渲染图表标题时暴露部分原始字段中的敏感标识符；
- **改造**：在沙箱输出管道挂载基于 Presidio / 规则字典的 Egress Sanitizer，拦截并重命名标准输出与 Matplotlib 生成的 SVG/PNG 文本中的手机号、姓名与内部密钥，杜绝数据漏逸。

3. **如何严密证明改动有效且无回归（工业级评测防线）**：
- **分析集防回归（Regression Testing）**：首先在 300 例日常分析集（Analysis Set）上运行端到端自动化测试，确保原有回答通过率（69.33%，208/300）与证据覆盖率无负向回归，重点校验净解决的 22 题持续稳定；
- **验证集盲测准入（Blind Validation Gate）**：研发探索期间，200 例验证集严格保持盲测未跑（Blind），彻底杜绝开发者的无意识过拟合与数据窥探（Data Snooping）。当两周重构代码经过 CI/CD 单元测试（`pytest`）与分析集对账彻底冻结后，作为正式发版前的终审门禁执行一次性盲测跑分，若验证集指标与分析集趋势一致且无断崖下跌，方可合并主干上线。

4. **核心代码：Milvus 逻辑别名原子切换与版本切换实现**：
```python
from pymilvus import utility, Collection

class ZeroDowntimeAliasManager:
    """基于 Milvus 别名机制的生产级零停机索引滚动切换"""
    def __init__(self, alias_name: str = "supermew_knowledge_active"):
        self.alias_name = alias_name

    def switch_to_new_collection(self, new_collection_name: str, old_collection_name: str):
        # 1. 确保新集合已完成向量与标量索引构建，并已 load 进内存
        new_col = Collection(new_collection_name)
        new_col.load()
        
        # 2. 原子修改别名指向，流量毫秒级无感切换
        utility.alter_alias(
            collection_name=new_collection_name,
            alias=self.alias_name
        )
        print(f"别名 {self.alias_name} 已成功指向 {new_collection_name}")
        
        # 3. 释放旧集合内存并延时异步销毁
        old_col = Collection(old_collection_name)
        old_col.release()
        # 异步调度清理任务: old_col.drop()
```

##### ❓ 面试官高频追问预判 (连环问攻防对决)

###### 🎯 追问 1：为什么研发探索期坚决不跑 200 道验证集？
- 🎯 **考官意图**：考察候选人对机器学习与工业级评测科学规范的认知。
- 🛡️ **攻防标准应答**：这是为了彻底避免“数据窥探偏差（Data Snooping Bias）”。如果在每次调优策略时都看验证集结果，工程师就会无意识地针对验证集的失败样本修改代码和 Prompt，导致验证集失去客观评估模型泛化能力的价值。因此我们严格将其保持盲测，仅在最终方案代码冻结后跑一次作为发版终审。
- ⚠️ **避坑要点**：千万不要编造虚假的日常调优验证集分数，说明严格盲测才是体现专业度的高分答案。

###### 🎯 追问 2：如果在 300 题分析集回归测试中发现有 2 题从原本答对变成答错了，你怎么决策？
- 🎯 **考官意图**：考察回归分析、Bad Case 归因与发布风险决策机制。
- 🛡️ **攻防标准应答**：严禁直接上线。立即调取这 2 题的 Trace 链路进行二分差分（Diff Analysis）：比对 Retrieval Chunk IDs、RRF 排序与 LLM 输入 Prompt。若发现是由于别名切换或新分块边界导致原本处于临界的证据被微弱降权，评估是否可以通过优化标题路由元数据修复；若属于无法兼顾的边缘 corner case，需组织技术评审，权衡全局正向收益（+22 题）与局部负向波动的业务风险后决定是否发版。
- ⚠️ **避坑要点**：不能轻描淡写说“净收益大直接上”，必须展示出对负向 Case 的严肃追查与风险意识。

###### 🎯 追问 3：Python 沙箱中如果是以图片（PNG/JPEG）形式渲染的图表，出口脱敏如何防止敏感数字泄露？
- 🎯 **考官意图**：考察深度数据安全与多模态脱敏设计。
- 🛡️ **攻防标准应答**：多层防御：第一层在输入端，沙箱接收到的 DataFrame 已经由 SQLGuard 针对敏感列（如身份证、薪资）做了哈希或掩码脱敏；第二层在代码生成 Prompt 中注入静态代码契约，禁止向图表注入原始 PII 字段；第三层在容器内提供标准可视化模板库（如 DataPilotViz），封装 Matplotlib 轴标签与 Hover 格式化器，统一进行脱敏渲染，杜绝直接将原始高密数据打在位图上。
- ⚠️ **避坑要点**：说明“输入前置脱敏”和“绘图组件封装”的纵深防御，比纯靠 OCR 图像后置识别要高效且可靠得多。
