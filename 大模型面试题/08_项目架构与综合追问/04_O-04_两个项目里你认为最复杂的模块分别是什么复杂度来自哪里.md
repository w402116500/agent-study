# O-04: 两个项目里你认为最复杂的模块分别是什么？复杂度来自哪里？

- **归属项目**：`两个项目通用` | **题目类型**：`深挖题` | **难度等级**：`进阶` | **核心主题**：`系统设计, RAG, Agent`
- **可信级别**：项目事实 / 当前代码

> 💡 **一句话速记结论**：
> SuperMew 最复杂在‘结构感知父子分块与 Auto-merging 上卷契约’，DataPilot 最复杂在‘受控工具循环的状态一致性、取消阻断与 SSE 先落库’。

##### 🎙️ 30 秒高频口答精要 (电梯演讲 / 直击要害)

SuperMew 复杂度来自非结构化文本的语义完整性治理：如何在 Markdown 解析后保持表格列表原子性、构建 L1/L2/L3 树状关系，并在检索阶段动态判定父级上卷，既不让上下文切碎，又不撑爆 Prompt 上下文；DataPilot 复杂度来自不可信模型与真实数据库/执行环境的受控交互：如何在动态循环中利用 sqlglot 做 AST 语法树级阻断、Docker 沙箱资源隔离、多源 Schema 快照版本冻结，以及实现断线精准恢复的全局单调 seq 事件流。

##### ⏱️ 60~120 秒深度展开 (系统架构 / 机制与推演 / 逐行源码讲解)

在两个系统的工程研发中，最复杂的模块分别在于并发与状态一致性治理：
1. **SuperMew 最复杂模块：多路检索自适应融合与 Auto-merge 父子协同**：
- **复杂度根源**：不仅要协同 Milvus 稠密向量与 BM25 稀疏检索，更要在毫秒级内解决碎片上下文缺失与上下文冗余的矛盾；
- **核心攻克点**：自适应父级上卷算法，通过树状溯源与去重逻辑，确保同一个 L1 章节下的多个命中片段既能补足表头上下文，又不会因父块重复填充导致 LLM 上下文窗口溢出；并在 Rerank 异常时毫秒级切回降级排序。

2. **DataPilot 最复杂模块：只读受控 SQL Guard AST 改写与执行中断审计**：
- **复杂度根源**：防范 LLM 的 SQL 注入幻觉（如嵌套危险函数、隐式事务、死锁）以及前端主动中断时的资源悬挂；
- **核心攻克点**：深度集成 sqlglot 解析器，对 AST 进行深度递归遍历校验白名单（限制只读、拦截多语句、强制注入 LIMIT 1000）；同时实现双向异步取消机制——当用户点击取消时，向后端广播取消信号，同时杀死数据库后端进程与模型生成 Task。

3. **核心代码：双向异步取消与 SQL Guard 拦截**：
```python
import asyncio
from sqlglot import parse_one, exp

class ManagedQueryExecutor:
    """受控查询执行器：兼顾 AST 防御与优雅取消"""
    def __init__(self, db_pool):
        self.pool = db_pool

    async def execute_query_with_cancellation(self, raw_sql: str, cancel_event: asyncio.Event) -> list:
        # 1. 严格 AST 校验与改写
        parsed = parse_one(raw_sql, read="postgres")
        if not isinstance(parsed, exp.Select):
            raise PermissionError("拦截非法语句：仅允许 SELECT 只读查询")
        
        # 2. 检查多语句（防止分号后注入 DROP/UPDATE）
        if len(raw_sql.strip().split(";")) > 2:
            raise PermissionError("拦截多语句查询：每次仅允许执行一条单语句")
            
        safe_sql = parsed.limit(1000).sql(dialect="postgres")
        
        # 3. 异步获取连接并监听前端取消信号
        async with self.pool.acquire() as conn:
            pid = await conn.fetchval("SELECT pg_backend_pid()")
            query_task = asyncio.create_task(conn.fetch(safe_sql))
            
            # 双向竞争：等待查询完成或取消事件激活
            done, pending = await asyncio.wait(
                [query_task, asyncio.create_task(cancel_event.wait())],
                return_when=asyncio.FIRST_COMPLETED
            )
            
            if cancel_event.is_set():
                # 主动向数据库发送终止信号，释放数据库锁资源
                # 依据 DataPilot 真实代码实现 (packages/data_gateway/adapters.py 及 mysql_adapter.py)
                if dialect in ("sqlite", "duckdb"):
                    connection.interrupt()
                elif dialect == "mysql":
                    control.exec_driver_sql(f"KILL CONNECTION {int(thread_id)}")
                query_task.cancel()
                raise asyncio.CancelledError("客户端已主动取消查询，数据库后端连接已释放")
                
            return query_task.result()
```

##### ⭐ 核心关键技术点 (回答骨架)

- ✔️ SuperMew：解决向量检索粒度（小）与大模型阅读理解粒度（大）的工程矛盾
- ✔️ DataPilot：解决模型自主决策的不可预测性与数据安全审计确定性的系统级矛盾
- ✔️ 复杂度均通过清晰的契约与防御性网关被系统收敛，而非依赖模型自觉

##### ❓ 面试官高频追问预判 (连环问攻防对决)

###### 🎯 追问对决：如果用户在 DataPilot 正在执行长查询时点击前端取消，底层两端（Gateway 与模型）如何优雅中断？

- 🎯 **考官意图**：考察异步信号传播、长任务资源回收与分布式取消链路。
- 🛡️ **攻防标准应答**：前端点击取消时发送 HTTP DELETE /runs/{run_id}，Gateway 立即触发该 Run 绑定的 asyncio.Event 取消标志位；数据库端依据数据源类型通过 SQLite/DuckDB 的 connection.interrupt() 或 MySQL 的 KILL CONNECTION {thread_id} 强制中断物理查询并释放连接；沙箱端执行 docker kill 杀死正在运行的 Python 容器；模型端直接关闭与大模型的 Streaming 通道并持久化 CANCELLED 终态事件，全链路无任何资源悬挂。
- ⚠️ **避坑要点**：不要说'直接把前端断开连接就完事了'，前端断开如果后端不主动 kill，数据库长事务会锁住整张表并耗尽连接池。

###### 🎯 追问对决：SuperMew 父级上卷后，如果连续命中同一个 L1 下的 5 个 L3，最终是送入 1 个 L1 还是 5 个 L3？

- 🎯 **考官意图**：考察分块合并去重逻辑与 Prompt 上下文 Token 控制能力。
- 🛡️ **攻防标准应答**：最终仅送入 1 个 L1。系统在 Auto-merging 阶段维护了树状祖先集合，当命中计数达到阈值且覆盖度超过该 L1 章节的 60% 时，系统直接提升为 1 个完整的 L1 节点，并在上下文中将其原本分散的 5 个子 L3 标记为已折叠吸收，既为大模型提供了连贯的整章上下文，又有效避免了重复内容对窗口的无效占用。
- ⚠️ **避坑要点**：千万不能说'送入 5 个 L3 和 1 个 L1'，这样会导致严重的上下文重复，破坏 Cross-Encoder 精排效果。

###### 🎯 追问对决：这两个最复杂的模块在本地如何编写自动化单元测试？

- 🎯 **考官意图**：考察工程素养、Mock 测试与边界场景覆盖实践。
- 🛡️ **攻防标准应答**：对 SQL Guard 模块，编写基于 pytest 的参数化测试集，传入包含盲注、CTE 递归、堆叠多语句、UNION 联合注入等 50+ 种恶意 SQL 用例，断言全部抛出 PermissionError；对 SuperMew 父子合并模块，使用固定 Mock Markdown 文本生成确定性树结构，断言不同命中分布下输出节点的 ID 集合与层级是否完全符合预期。
- ⚠️ **避坑要点**：切忌回答'在界面上手工点一点测的'，必须强调基于 pytest 的自动化单元回归与 Mock 边界覆盖。

##### 🛡️ 系统设计防御边界与权衡 (Anti-Goals / 放弃的假设)

- 🛑 SuperMew 没有实现多模态图片向量检索，仅依赖 MinerU OCR 识别出的文字与表格
- 🛑 DataPilot Python 沙箱未接入复杂分布式 Spark 计算，仅用于单机数据重采样与图表渲染
