# O-11: 建立的评测或可观测性闭环如何定位“召回、排序、回答”中的问题？

- **归属项目**：`两个项目通用` | **题目类型**：`证据核验题` | **难度等级**：`进阶` | **核心主题**：`评测, 系统设计, RAG, Agent`
- **可信级别**：项目事实 / 当前代码

> 💡 **一句话速记结论**：
> 系统通过构建‘阶段分离的 Trace 埋点’与‘固定单变量基准题库’，将失败精准归因到解析、召回、排序、上下文或生成层。

##### 🎙️ 30 秒高频口答精要 (电梯演讲 / 直击要害)

定位机制由两部分组成：第一，全链路可观测 Trace：SuperMew 在单次请求中分别记录‘两路初筛召回列表及得分、RRF 重排结果、Auto-merging 上卷前后块对比、Qwen 精排后 Top 8 及模型引用’；第二，分层评测闭环：利用 300 道冻结题集，定义命中率（Recall@K）、重排质量（MRR/NDCG）、证据覆盖率与回答忠实度。通过阶段产物对比，哪一层掉分就能立刻定位到具体的模块缺陷，绝不盲目归咎给大模型。

##### ⏱️ 60~120 秒深度展开 (系统架构 / 机制与推演 / 逐行源码讲解)

建立闭环可观测性与自动化评测体系，核心在于对“召回、排序、回答”实施单变量指标解耦：
1. **三阶段问题解耦与归因公式**：
- **检索召回层（Hit Rate@30 & Recall@30）**：验证初筛是否把黄金证据纳入候选池。若该指标低，归因为分块切断上下文或词表不匹配，定位为 MinerU 解析或分块粒度问题；
- **重排精排层（MRR@8 & Context Precision）**：验证黄金块是否排在 Top-8。若召回高但精排后黄金块被挤出 Top-8，直接归因为 Qwen Reranker 超参数或 Cross-Encoder 打分失准；
- **答案生成层（Faithfulness & Answer Relevance）**：验证模型是否忠于检索证据。若上下文精准但回答错误，定位为大模型指令遵循能力差或 Prompt 提示词污染。

2. **自动化评测流水线运作流程**：
- 我们构建了由 300 道真实企业问题构成的黄金测试集（标注了 query、expected_chunk_ids、ground_truth）；
- 每次算法迭代（如调整分块参数或改写 Prompt），脚本自动化回放并生成 `eval_report.json`，输出全景混淆矩阵。

3. **核心代码：全链路指标采集与归因计算器**：
```python
from typing import List, Dict

class EvaluationHarness:
    """召回、排序与答案三阶段解耦评测引擎"""
    def evaluate_query_case(
        self, 
        golden_ids: List[str], 
        retrieved_ids: List[str], 
        reranked_ids: List[str]
    ) -> Dict[str, float]:
        # 1. 召回层指标 (Hit Rate)
        hit_retrieval = any(gid in retrieved_ids for gid in golden_ids)
        
        # 2. 精排层指标 (MRR@8)
        mrr = 0.0
        for rank, cid in enumerate(reranked_ids[:8]):
            if cid in golden_ids:
                mrr = 1.0 / (rank + 1)
                break
                
        # 3. 错误归因诊断
        failure_stage = "NONE"
        if not hit_retrieval:
            failure_stage = "INGESTION_OR_RETRIEVAL"  # 解析/分块/初筛失败
        elif mrr == 0.0:
            failure_stage = "RERANKER_SUPPRESSION"    # 被精排误杀
            
        return {
            "hit_rate": 1.0 if hit_retrieval else 0.0,
            "mrr_at_8": mrr,
            "failure_stage": failure_stage
        }
```

##### ⭐ 核心关键技术点 (回答骨架)

- ✔️ 单次请求拆分 5 个独立 Trace 切片，杜绝端到端黑盒归因
- ✔️ 区分召回缺失（看初筛）、排序下沉（看精排前/后）与生成幻觉（看 Top 8 上下文与答案一致性）
- ✔️ 评测集必须标注黄金 Chunk ID 或关键事实，才能实现自动化分层打分

##### ❓ 面试官高频追问预判 (连环问攻防对决)

###### 🎯 追问对决：如果一次问答既存在初筛低分，模型又胡编了答案，评测系统如何算分？

- 🎯 **考官意图**：考察复合错误归因、责任链判定与防漏测机制。
- 🛡️ **攻防标准应答**：评测体系遵循'漏斗最前序责任原则'：将故障根因归档在'检索召回失败'（Ingestion/Retrieval Failure），因为输入给生成模型的上下文本身就是残缺的，模型幻觉是必然结果；但同时在指标中独立打上 `Faithfulness=0` 的标记，防止该题目掩盖大模型抗幻觉能力的缺陷，并在错误归因大盘中记录为复合级联缺陷。
- ⚠️ **避坑要点**：不要把所有问题都笼统怪在大模型幻觉上，必须分清前序检索失效与后序生成幻觉的先后因果关系。

###### 🎯 追问对决：在没有人工标注答案的大规模线上日志中，如何无监督地发现低质回答？

- 🎯 **考官意图**：考察生产环境监控、无监督/弱监督质量挖掘与在线数据闭环实践。
- 🛡️ **攻防标准应答**：通过三重无监督代理指标进行实时挖掘：1) **检索置信度告警**：初筛最高分低于阈值或 Reranker Top-1 分数 < 0.2；2) **引用密度检测**：生成回答中包含未被角标覆盖的长句断言，判定为未绑定证据；3) **隐式负反馈**：用户复制回答后未采纳，或在 30 秒内输入同义重问，直接触发告警并将问答对投递入审查队列。
- ⚠️ **避坑要点**：不要说'线上只能靠人工天天看'，必须提出自动化的代理信号（引用覆盖率、置信度阈值、交互负反馈）。

##### 🛡️ 系统设计防御边界与权衡 (Anti-Goals / 放弃的假设)

- 🛑 离线自动化评测依赖 Judge 模型打分，存在微小的评测一致性方差，需搭配定向人审抽检
- 🛑 高并发生产环境下只采集阶段耗时与元数据，完整大块内容 Trace 需进行采样保存以节省磁盘
