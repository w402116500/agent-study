##### ⏱️ 60~120 秒深度展开 (系统架构 / 机制与推演 / 逐行源码讲解)

在项目中我负责的核心工程边界是两套系统的“安全防御网关”与“混合检索协同管线”的代码编写与评测：
1. **核心功能落地：基于 sqlglot 的 SQL Guard 安全门禁**：
- **需求背景**：大模型生成的 SQL 极不稳定，极易产生包含 `DROP/DELETE`、多语句注入或超大数据量全表扫描，威胁企业生产数据库安全；
- **从需求到代码实现**：我主导编写了 `SQLGuard` 模块，采用 AST 递归遍历语法树，建立只读白名单机制，彻底拦截 DDL/DML 与系统函数；强制解析 LIMIT 子句，对无限制或超出阈值的查询重写为 `LIMIT 1000`；并对查询字段进行元数据映射，注入脱敏规则；
- **工程成果**：在 200+ 恶意注入测试集下实现 100% 拦截率，杜绝了任何越界访问。

2. **核心代码：我独立编写的 SQLGuard 核心拦截器**：
```python
import sqlglot
from sqlglot import exp

class SQLGuard:
    """由我独立实现的生产级只读 SQL 门禁模块"""
    FORBIDDEN_EXPRESSIONS = (
        exp.Insert, exp.Update, exp.Delete, exp.Drop, 
        exp.AlterTable, exp.Create, exp.Command
    )
    
    def validate_and_rewrite(self, sql_query: str, max_limit: int = 1000) -> str:
        # 1. 严格语法树解析
        try:
            tree = sqlglot.parse_one(sql_query, read="postgres")
        except Exception as e:
            raise ValueError(f"SQL 语法解析失败，拦截非法输入: {str(e)}")
            
        # 2. 递归遍历 AST 拦截任何禁止的写操作或命令
        for node in tree.walk():
            if isinstance(node, self.FORBIDDEN_EXPRESSIONS):
                raise PermissionError(f"安全违规：检测到非只读操作 [{type(node).__name__}]，严禁执行！")
                
        # 3. 根节点必须是 Select
        if not isinstance(tree, exp.Select):
            raise PermissionError("安全违规：顶层查询必须是 SELECT 语句")
            
        # 4. 强制重写注入安全 LIMIT 1000
        limit_node = tree.find(exp.Limit)
        if not limit_node:
            tree = tree.limit(max_limit)
        else:
            val = int(limit_node.expression.this)
            if val > max_limit:
                limit_node.expression.set("this", max_limit)
                
        return tree.sql(dialect="postgres")
```

- 🛡️ **攻防标准应答**：确实踩过坑：最初用 `isinstance(tree, exp.Select)` 时，合法的 `WITH cte AS (SELECT ...) SELECT ...` 顶级节点实际是 `exp.Select` 但外层带有 `with` 属性，如果误判顶级类型就会报错；更坑的是 CTE 内部如果被模型写入了 `WITH deleted AS (DELETE FROM ... RETURNING *)` 这种带副作用的写 CTE，简单判断外层是无法拦截的。我的解决方案是在 `tree.walk()` 递归中逐层扫描每一个节点，确保即使藏在 CTE 内部的 DML 也被一网打尽。
- ⚠️ **避坑要点**：这道题是绝佳的真项目试金石，切忌回答'没遇到过任何问题'，说出 CTE 的具体 AST 陷阱能瞬间拉满可信度。
