# RED-006: Redis 不可用时如何降级？哪些错误不能静默吞掉？

#### 简要回答

缓存连接失败可按未命中回源关系库，保证核心问答仍能运行，但要限制回源并记录指标，防止 Redis 故障把数据库打垮。参数错误、权限错误、文档版本不匹配和安全拒绝不能统称缓存未命中，更不应让错误数据悄悄返回。


#### 详细解析


##### 1. 1. 可降级与不可降级

缓存服务短暂连接失败通常可回源，但回源也需要超时、并发与结果限额。若缓存内容已明确过期，可回源；若版本校验不通过，应重新读取正确版本或失败。DataLink 的临时不可用降级到 Schema-only 是有条件的，不能把所有错误都降级。


##### 2. 2. 防止级联故障

回源限流、短路与小范围 stale 数据能保护 PostgreSQL；监控 cache hit、miss、error、回源耗时和数据库连接等待，恢复后逐步放量。若代码捕获所有 Exception 后只 return None，业务层仍要有可观测日志，否则故障会表现为回答变慢或数据库被打满。


##### 3. 3. 代码事实与改进

RAG cache.get_json/set_json/delete 捕获异常，get 返回 None，因此缓存故障走回源路径。这个设计体现核心业务不强依赖 Redis，但没有据此声称做了熔断、回源限流或告警。面试可以主动说出下一步改进，显示知道降级的代价。


#### 面试总结

- 缓存可用性降级不等于数据安全降级
- 回源要限流和观测
- 错误分类决定能否 fallback
- 当前代码按未命中处理 Redis 异常


#### 递进追问与参考答案


**追问 1：Redis down 时所有请求回源会怎样？**

可能形成数据库洪峰。应对回源设置并发上限、超时和有限结果，必要时暂时拒绝低优先级请求或返回可接受旧值。恢复 Redis 后应渐进回填，不能让所有请求同时重建缓存。


**追问 2：缓存反序列化失败算 miss 吗？**

可作为当前键不可用并回源，但应记录数据损坏/版本错误，而不是和正常 miss 混在同一指标里。若错误反复出现，需要删除或隔离坏键并排查写入版本。
