# BE-001: FastAPI 如何处理 async def 与同步 def？同步 SDK 怎么避免阻塞？

原题关联：PY-11：FastAPI 如何处理 async def 与同步 def 路由？Docker 沙箱/同步 SDK 任务怎样避免阻塞事件循环？

对应简历：熟悉 FastAPI；Python 异步编程


#### 简要回答

FastAPI 的 async 路由直接在事件循环中运行，同步 def 路由和依赖由线程池执行。async 路由里手动调用普通同步函数不会被自动卸载，因此应检查真实 SDK，优先异步客户端，必要时受限线程或进程执行。RAG 当前关系库与 Redis 封装是同步的，不能把服务描述成所有 I/O 全异步。


#### 详细解析


##### 1. 1. 框架边界与普通函数边界

路由和 Depends 是框架掌握的调用位置，FastAPI 可以根据函数类型安排执行；普通 helper 是用户直接调用的函数，框架不会自动识别里面有阻塞 I/O。把同步数据库函数放进 async 路由，只改变外层声明，不改变驱动等待方式。需要看调用链最底层是 await、同步网络还是 CPU 计算。


##### 2. 2. 三种处理方式的取舍

如果客户端支持异步，可使用原生 await；如果只有同步 API，可将完整同步工作单元卸载到有限线程；纯 Python 重计算可独立进程。线程会引入排队与上下文传播问题，会话也不能随意跨线程共享。不能只把最后一条 db.query 移到线程，却让 Session 在不同线程之间交替使用。


##### 3. 3. 如何证明修改有效

同时发一个慢依赖请求和一个轻量请求，记录轻量请求延迟、SSE 心跳与线程池排队，而非只看慢请求的总时间。DataPilot 沙箱使用异步子进程读取与有限超时，可作为另一种等待外部程序的例子。部署 Worker 数与数据库连接总量也需一起预算；更多 Worker 不会自动消除外部服务瓶颈。


#### 面试总结

- 同步 helper 不自动进线程池
- 完整工作单元明确执行环境
- 异步子进程适合程序等待
- 用事件循环延迟验证


#### 递进追问与参考答案


**追问 1：改成 def 路由就全解决了吗？**

只解决该路由占用事件循环的部分问题。线程池容量仍有限，同步调用需要超时，CPU 工作仍可能受 GIL 限制。也不能把需要异步流式等待的逻辑机械改为同步；应根据调用链选择执行模型并限制负载。


**追问 2：提高 Worker 数要注意什么？**

每个进程会有独立内存、连接池和模型客户端，数据库连接总量可能成倍增长。进程内 Task、锁、队列也不会自动共享。应确认业务状态可跨进程持久访问，再按内存、连接容量和实际吞吐设 Worker 数。
