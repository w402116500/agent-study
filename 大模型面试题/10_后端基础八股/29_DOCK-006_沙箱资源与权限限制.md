# DOCK-006: 无网络 Python 沙箱还要配置哪些资源与权限限制？

原题关联：新增：Docker 部署与代码沙箱

对应简历：Python 在无网络 Docker 沙箱执行


#### 简要回答

无网络只减少联网访问面，还需要 CPU、内存、进程数、执行时间、非 root、去 capabilities、no-new-privileges、只读根文件系统和受控挂载。DataPilot 当前命令包含这些限制项，但实际数值来自配置且需验证；不能声称配置完成后绝对无逃逸或无泄漏。


#### 详细解析


##### 1. 1. 为什么要多层约束

死循环消耗 CPU，大对象耗尽内存，递归起进程消耗 PID；三者要分别限制。CPU quota 是配额，不等于只运行固定一核；内存上限与 OOM 处理、swap 语义也需结合环境。超时是墙钟预算，涵盖启动与执行，不能仅靠 CPU 限额等待脚本自己结束。


##### 2. 2. 权限与文件系统

非 root 缩小权限但不自动禁止读取所有挂载，cap-drop 和 no-new-privileges 进一步限制能力提升；只读根目录减少修改。仍需可信镜像、宿主运行时更新、最小输入和输出准入。网络关闭不能防从 stdout 或产物输出敏感数据，结果遮蔽也不保证 Python 派生内容全被识别。


##### 3. 3. 当前源码准确表述

docker_sandbox.py 命令构造处包含 network、cpus、memory、pids-limit、cap-drop、security-opt、user、read-only。可以逐项解释保护对象，并说明有单独执行超时和清理。应避免把源码配置等同已做真实攻击验证，本轮未运行沙箱，17条 MySQL 用例也不验证容器逃逸。


#### 面试总结

- 网络资源权限三层约束
- 超时与 CPU 配额不同
- stdout 与产物仍需治理
- SQL 用例不证明沙箱逃逸安全


#### 递进追问与参考答案


**追问 1：--network none 后代码还能泄漏吗？**

可以通过已允许的 stdout、文件产物或错误信息带出输入数据。应最小化输入、限制输出与审查敏感内容，不能把无网络当完整数据防泄漏。内核与宿主漏洞也仍是不同风险。


**追问 2：如何证明资源限制生效？**

在隔离测试环境用受控 CPU、内存、进程数和超时样例，查看容器 inspect 与实际退出/错误分类，确认宿主未受影响。不要只看命令参数字符串，本轮没有执行这类验证。
