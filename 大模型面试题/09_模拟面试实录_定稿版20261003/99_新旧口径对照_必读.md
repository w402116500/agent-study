### 2. 敏感字段脱敏的实现层

| | 口径 |
|---|---|
| 旧题库 | [07/32 T-D-04](../07_DataPilot项目深挖/32_T-D-04_mask_fields=null、mask_fields=[.md) 攻防应答：「通过 sqlglot AST 建立血缘映射（Lineage Tracking），追踪投影项底层物理列名，识别别名后脱敏」 |
| 09 模块（M-11） | **脱敏不靠 SQLGlot**——SQLGlot 只负责 SQL 安全校验；脱敏由 **Data Gateway** 在 SQL 执行后、结果返回前，按**返回结果列名**与数据源配置的 `mask_fields` 做**大小写不敏感匹配**，命中值替换为 `***`；发生在数据进入 Agent / Artifact **之前** |

⚠️ 面试里不要说「sqlglot 做脱敏 / 血缘映射」。`mask_fields=null / [] / 非空列表` 的语义两版一致，可放心引用 T-D-04；但匹配机制的实现层按 [M-11](./11_M-11_敏感字段遮蔽怎么做.md) 口径回答。

## 三、核对过一致、无需担心的表述

以下两处容易怀疑有冲突，但逐条核对后旧题库与 09 口径一致，照常复习即可：

- **LIMIT 处理**：不是直接拒绝没写 LIMIT 的 SQL，而是自动注入默认 LIMIT、过大时收紧——[07/30 T-D-02](../07_DataPilot项目深挖/30_T-D-02_sqlglot_Guard_如何拒绝_DDLDML、多语句、.md)、[08/01 O-01](../08_项目架构与综合追问/01_O-01_介绍一下两个项目分别解决什么问题整体架构如何分层.md) 与 [M-10](./10_M-10_为什么不能只靠只读账号和SELECT前缀.md) 修正后口径一致。
- **沙箱数据获取**：连接型数据源（远程 MySQL）的 `input/` 为空；模型需要的数据先经 `run_sql_readonly` 查出、再内联进脚本，系统不会自动把 SQL 结果挂载进沙箱——[07/34 T-D-06](../07_DataPilot项目深挖/34_T-D-06_Python_连接型_Run_的_input_为什么可能为空.md) 与 [M-13](./13_M-13_Python为什么必须在Docker沙箱执行.md) 修正后口径一致。
