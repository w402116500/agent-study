# M-12: 为什么不能等最终答案生成前再脱敏？

### 面试问题

为什么一定要在 Data Gateway 返回结果的时候脱敏？如果等最终答案生成之前再把手机号、身份证这些内容替换掉，不也能保证用户看不到吗？

### 我的原回答

但是这个时候模型不也已经获取到敏感信息了吗？这个目的一方面是防用户看到，另一方面是防模型。如果模型在前面已经看到，后续结果的话就没意义了。

### 关键修正

思路完全正确，需要把“没意义”说得更精确：

- 最终答案前脱敏，只能保护**展示层**。
- 如果原始敏感值已经进入 ToolMessage、Agent 上下文或其他后续链路，就已经不能保护**模型输入侧**了。

### 修正版口述答案

如果等最终答案生成前才脱敏，模型其实已经看过原始敏感数据了。这样最多只能保证最终用户看不到，但不能保证敏感信息没有进入模型上下文。

所以我把脱敏放在 Data Gateway 返回查询结果的时候做，保证进入 Agent 后续链路的就是已经遮蔽的数据。我的目标不只是保护最终展示，而是尽量让敏感原值不要越过数据访问这一层。

### 一句话记忆

**脱敏要发生在模型之前，而不是答案之前。**
