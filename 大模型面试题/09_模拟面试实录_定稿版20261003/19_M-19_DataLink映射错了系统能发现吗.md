### 面试问题

如果 DataLink 恰好把业务字段映射错了，但 SQL 合法、查询结果也真实，甚至三阶段事实校验都通过了，你这套系统能发现吗？如果发现不了，你会怎么改进？

### 我的原回答

这个的话确实判断不了。我最理想的办法就是去审计和人工修订。

我们每轮的 DataLink 调用结果都会去带上标注和源，去方便我们审核错误点。

### 关键修正

1. 这个边界判断是对的：现有系统不能自动判断所有业务语义错误。
2. 更准确的说法不是“每个结果都有完整证据 JSON”，而是：语义关系尽量保留来源、置信度和可用证据；系统记录当次消费的图版本和安全语义投影。
3. 审计的价值是定位“模型当时到底看到了哪条语义映射或关系”。
4. 人工修订不应该只修一次回答，而应该修正**语义资产本身**，让后续 Run 都受益。

### 修正版口述答案

这种情况我确实没法靠现有的 SQL 或事实校验自动发现，因为它查到的数据可能完全真实，只是业务语义选错了。

我的处理思路主要是审计加人工修订。DataLink 返回的关系会保留来源、置信度以及可用的证据信息，系统也会记录当次使用的图版本和语义投影，所以如果线上发现答案语义错了，我能追到当时模型到底参考了哪条映射或者哪条关系。

确认是 DataLink 本身的问题以后，我不会只改单次回答，而是直接修订对应的概念、字段映射或者关系，再发布新的语义图版本，让后续 Run 使用修正后的结果。

所以这里我的目标不是声称系统能自动识别所有语义错误，而是让这种错误 **可追踪、可修正、修一次以后能沉淀下来**。

### 一句话记忆

**语义错误未必能自动判，但要做到可追踪、可修订、可沉淀。**
