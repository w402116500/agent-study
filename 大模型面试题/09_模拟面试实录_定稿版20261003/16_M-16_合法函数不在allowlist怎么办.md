# M-16: 线上合法业务确实需要一个当前不在 allowlist 里的 MySQL 函数，怎么办？

### 面试问题

如果线上真的遇到一个合法业务查询，必须使用某个现在不在 allowlist 里的 MySQL 函数，你会怎么处理？会不会让模型自己把它加进白名单？

### 我的原回答

这个的话，必须得专门针对这个函数去做定向测试。我们当然不是让模型去把它加进白名单。

目前我们的所有安全都是由系统去确定性判断的，不能让模型自行判断是否安全。只有经过校验过后的函数，才能自己对代码层去加入函数。

### 关键修正

1. 安全策略的修改权不能交给模型，这一点非常关键。
2. 新函数需要做定向安全测试，确认它是否存在文件访问、锁、外部资源等危险能力。
3. 通过后，应由开发者通过代码变更显式加入 allowlist。
4. 同时应补对应的正向和负向回归测试。

### 修正版口述答案

如果线上确实有合法业务需要一个当前没放行的 MySQL 函数，我不会让模型自己决定放行。

我会先针对这个函数做定向测试，确认它的能力边界，包括正常调用以及有没有文件访问、锁、外部资源这类风险。确认安全以后，再由开发者通过代码变更显式加入 allowlist，同时补对应的正向和负向回归测试。

因为我这套安全设计的原则一直是确定性判断：模型可以生成 SQL，但不能修改安全策略本身。

### 一句话记忆

**模型只能使用安全策略，不能修改安全策略。**
