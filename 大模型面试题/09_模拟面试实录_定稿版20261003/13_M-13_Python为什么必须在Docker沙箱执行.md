### 面试问题

你简历里写了 Python 代码在无网络 Docker 沙箱中隔离执行。为什么不直接在 FastAPI 后端进程里执行模型生成的 Python？你这个沙箱主要是在防哪些风险？

### 我的原回答

因为大模型生成的代码的安全性我不能保证。我是让模型生成 Python 代码的文本后，将该文本弄成一个 py 文件，然后让系统放进去一个做过安全管理的 Docker 沙箱。

这个沙箱无网络，独立进程与后端进程零共享内存，并且只读，限制资源防止卡死。另外只挂载我们核验过的数据快照文件，也就是 Agent 之前查询结果内容会弄成一个文件放进沙箱。

还有一点命令写死为 `python analysis.py`，防止执行任意命令。

### 关键修正

1. 根本原因说对了：模型生成的 Python 是不可信代码，不能假设它安全。
2. 当前实现确实包括：无网络、CPU/内存/进程数限制、超时、非 root 用户、drop capabilities、`no-new-privileges`、根文件系统只读、脚本和输入只读挂载、固定执行入口 `python analysis.py`。
3. “零共享内存”太绝对，更稳妥地说“**不在 FastAPI 进程内执行，而是在独立容器进程中隔离执行**”。
4. **当前不是把前面的 SQL 查询结果自动做成文件挂进沙箱。**
5. 文件型数据源挂载的是当前 Run 固定下来的 CSV / SQLite 输入快照。
6. 不是所有地方都只读：模型明确声明的输出路径需要可写，否则无法产出图表和文件。

### 修正版口述答案

因为 Python 是模型生成的，我不能假设这段代码一定安全，所以不会直接在 FastAPI 进程里 `exec`。

我的做法是先把模型生成的代码保存成固定的 `analysis.py`，然后放到一次性的 Docker 沙箱里执行。

沙箱首先是无网络的，避免脚本往外发数据或者联网下载东西；其次容器根文件系统、脚本和输入数据默认只读，只给模型提前声明好的输出文件开放写权限；另外还限制 CPU、内存、进程数和执行时间，避免死循环或者资源打满。

文件型数据源只会把当前 Run 固定的输入快照以只读方式挂进去，不会把宿主机目录随便暴露给脚本。容器也是非 root 运行，并去掉额外 capability。

最后执行入口也是后端固定的 `python analysis.py`，模型只能提供脚本正文和受限的输出声明，不能自己拼 Docker 参数或者任意 shell 命令。

核心就是：**模型可以写分析逻辑，但不能决定它获得什么系统权限。**

### 一句话记忆

**模型可以写分析逻辑，但不能决定它获得什么系统权限。**
